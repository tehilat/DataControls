# כלי AI ששימשו בפיתוח

## סיכום

| כלי | מטרות עיקריות |
|---|---|
| Claude Code (מודל Claude Opus 5.5) | מימוש, בדיקות ותיעוד. עבודה ב-Plan Mode: סקירה ואישור של כל תוכנית לפני כתיבת קוד |
| Claude (צ'אט, Claude Opus 5.5) | תכנון ארכיטקטורה ותחום הנתונים, סקירה ביקורתית של כל תוכנית לפני אישורה, הגדרת סביבת הפיתוח, ובדיקת UI |

## Claude Code (Claude Opus 5.5)

סוכן קוד שרץ בטרמינל, בתוך ה-repository.

**מטרות השימוש:**
- **מימוש:** סקריפטי ה-DB (סכמה, נתונים, Metadata, בקרות, הרשאות, אימות), מנוע הבקרות ב-.NET (Binder, QueryBuilder,
  Runner, סיבות חריגה), שכבת ה-API, שירות ה-AI ב-Python וחיבורו ל-.NET, וה-Frontend ב-Angular (רשימת בקרות, בונה
  תנאים רקורסיבי, מסך תוצאות, היסטוריה ומסך "צור בעזרת AI").
- **בדיקות:** כתיבה והרצה של בדיקות xUnit, pytest ו-Angular (unit, API, אינטגרציה מול ה-DB, ניסיונות injection),
  ובדיקות end-to-end מול השירותים הרצים. בסיום: 304 בדיקות .NET, 98 בדיקות Python ו-12 בדיקות Angular.
- **תיעוד:** `CLAUDE.md`, `docs/architecture.md`, `ai-service/README.md`, `README.md` ומסמכי ההגשה.

**אופן העבודה:**
- **מפרט לפני קוד:** את שלב בסיס הנתונים הגדרתי במפרט מפורט (`docs/db-instructions.md`): תחום הנתונים, 14 מקרי
  השגיאה, מקרי גבול תקינים, מבנה ה-JSON של בקרה ודרישת אימות. ה-DB נבנה לפי המפרט.
- **Plan Mode:** לפני כל שלב, Claude Code הציג תוכנית. כל תוכנית נסקרה ותוקנה לפי הצורך לפני האישור (ראו דוגמאות בהמשך).
- **שלבים קטנים, שכבה אחת בכל פעם:** DB, מנוע, API, שירות AI, חיבור ה-AI, Frontend. כל שלב בענף `feature/*` נפרד,
  ומוזג ל-`main` רק אחרי שכל הבדיקות עברו.
- **עבודה מקבילה:** שירות ה-Python וחיבור ה-AI ל-.NET נבנו בסשן נפרד, ב-`git worktree` נפרד, במקביל ל-API ול-Frontend,
  והענפים מוזגו בסוף.
- **`CLAUDE.md`** כמסמך הנחיות קבוע בפרויקט: מטרות, כללי עיצוב (בלי שמות טבלאות ושדות בקוד, בטיחות SQL), פרטי הסביבה,
  קונבנציות והוראות הרצה. הוא עודכן בסוף כל שלב.
- **אימות אחרי כל שלב:** build, הרצת כל הבדיקות ועדכון התיעוד. בסוף בוצעה בדיקת "התקנה מאפס" לפי ה-README.

**החלטות שקיבלתי במהלך העבודה:**
- **שמירת תוצאות ההרצה בטבלה** (`ctl.ControlRunViolations`) ולא בזיכרון או בהרצה חוזרת לכל עמוד. כך מתקבלת תמונת מצב
  קבועה, היסטוריה של כל הרצה, ו-paging וחיפוש ב-SQL.
- **מבנה הקטלוג שנשלח ל-AI:** נתיבי שדות שטוחים (למשל `Drone.Hub.IsActive`) במונחים עסקיים בלבד, בלי שמות פיזיים.
- **פירוש "משלוח באיחור"** כמשלוח שנמצא בדרך זמן רב, כי בנתונים אין מועד מסירה מתוכנן. ה-AI מסמן זאת כהנחה,
  באזהרה וברמת ביטחון נמוכה.
- **הצעת AI לא תקינה מחזירה 200 עם `isValid=false`** ולא 400, כדי שהמשתמש יוכל לפתוח אותה בעורך ולתקן.
- **השבתה במקום מחיקה** לבקרה עם היסטוריית הרצות, ונעילה אופטימית (`rowVersion`) בעריכה.

**דוגמאות למקומות שבהם תיקנתי או כיוונתי את הכלי:**
- **התאמה לסביבה:** שם השרת `localhost\SQLEXPRESS` והפרמטר `-C` ב-sqlcmd. במקום משתמשי SQL עם סיסמה, שלא עובדים
  ב-SQL Express עם אימות Windows בלבד, משתמשים `WITHOUT LOGIN` והרצה בתוך `EXECUTE AS USER`.
- **התנגשות שמות:** שינוי שם הטבלה `ops.Operators` ל-`ops.Pilots`, כדי שלא תתבלבל עם `meta.Operators` (אופרטורי השוואה).
- **הגדרה עמומה:** הגדרת "רחפן בשירות" כ-`Status = Active`, כדי שבקרה 7 ובקרה 13 לא יתפסו את אותה רשומה.
- **תאריכים "מתיישנים":** הנתונים התקינים הוזזו לפחות 365 יום קדימה, כדי שהבקרות יישארו נכונות גם שבועות אחרי טעינת
  הנתונים. נוספה הרצה של `99_verify.sql` גם אחרי סקריפט ההדגמה `06`.
- **חיזוק המנוע:** ולידציית טווחים (`offsetDays`, ערכים מספריים) לפני הגעה ל-SQL, פרמטרי טקסט כ-nvarchar עם בדיקות
  בעברית, וטיפול בערך של רווחים בלבד כערך ריק.
- **מיון וסינון לפי סוג נתון:** בתוכנית המקורית התוצאות היו ממוינות כמחרוזת (`10` לפני `9`). דרשתי מיון לפי טיפוס
  (`TRY_CONVERT` מתוך קבוצה קבועה של ביטויים) ובדיקות לכך. כמו כן, הגבלת `preview` ל-100 שורות.
- **ממצאים מבדיקת ה-UI:** פס גלילה מיותר וגלישה אופקית, הצגת מזהה הרשומה במקום מספר שורה, ניסוח ניטרלי לסיבת חריגה
  ("כתובת: חסר ערך" במקום "כתובת ריק"), ומעבר מהיר בין "וגם" ל"או" בבונה התנאים.
- **מגבלה שזוהתה בבדיקה ידנית:** אי אפשר להגדיר בקרה על קשר הפוך (משלוח שיצא בזמן התראת מזג אוויר במוקד שלו). המגבלה
  תועדה יחד עם תכנון הרחבה (תנאי `exists`).

## Claude (צ'אט)

**מטרות השימוש:**
- **תכנון ארכיטקטורה:** חלוקה לשכבות (Domain, Application, Infrastructure, Api), שכבת ה-Metadata כמפתח לגנריות, שמירת
  בקרה כ-JSON ולא כ-SQL, חלוקה לסכמות (`ops`, `meta`, `ctl`), הפרדת שירות ה-AI ל-Python, והחלוקה לשלבים.
- **סקירת תוכניות:** סקירה ביקורתית של כל תוכנית ש-Claude Code הציע ב-Plan Mode, ואיתור בעיות לפני כתיבת הקוד
  (הדוגמאות בסעיף הקודם).
- **הגדרת סביבה:** התקנת Python, .NET 10 ו-Angular CLI. הגדרת npm ו-pip מאחורי סינון TLS: חילוץ תעודת ה-CA של הסינון
  ממאגר התעודות של Windows והגדרתה (`cafile`, `NODE_EXTRA_CA_CERTS`, `pip config`). חיבור ל-SQL Server Express עם
  תעודה self-signed.
- **ניהול זמנים:** תכנון סדר העבודה, והרצה מקבילה של שני סשנים של Claude Code.

## מה נבדק ידנית

- סקירת כל תוכנית לפני אישורה, וסקירת הסיכום של כל שלב (בדיקות שעברו, שינויים מהתוכנית, החלטות פתוחות).
- בדיקת ה-UI בדפדפן: עברית ו-RTL, רשימת הבקרות וסינון, מספרי החריגות מול `99_verify.sql`, ויצירת בקרה חדשה מאפס
  ("לקוח ללא כתובת", שמחזירה את לקוח 8) עם תצוגה מקדימה, שמירה והרצה.
- מסך התוצאות: paging, חיפוש וסינון, והיסטוריית הרצות.
- זרימת ה-AI: הצעה, פתיחה בעורך ואישור. גם התנהגות המערכת כששירות ה-AI אינו זמין.
