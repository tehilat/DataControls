## Claude Code (Claude Opus 5.5)

סוכן קוד שרץ בטרמינל, בתוך ה-repository.

**מטרות השימוש:**
- **מימוש:** סקריפטי ה-DB (סכמה, נתונים, Metadata, בקרות, הרשאות, אימות), מנוע הבקרות ב-.NET (Binder, QueryBuilder,
  Runner, סיבות), שכבת ה-API, שירות ה-AI ב-Python וחיבורו ל-.NET. `[להשלמה: Frontend]`
- **בדיקות:** כתיבה והרצה של בדיקות xUnit ו-pytest (unit, API, אינטגרציה, ניסיונות injection), ובדיקות end-to-end ידניות
  מול השירותים הרצים.
- **תיעוד:** `CLAUDE.md`, `docs/architecture.md`, `ai-service/README.md` ומסמכי ההגשה.

**אופן העבודה:**
- **Plan Mode:** לפני כל שלב, Claude Code הציג תוכנית. סקרתי ואישרתי כל תוכנית, ולעתים תיקנתי אותה, לפני שנכתב קוד.
- **שלבים קטנים, שכבה אחת בכל פעם:** DB, מנוע, API, שירות AI, חיבור ה-AI, Frontend. כל שלב בענף `feature/*` נפרד,
  ומוזג ל-`main` רק אחרי סקירה.
- **`CLAUDE.md`** כמסמך הנחיות קבוע בפרויקט: מטרות, כללי עיצוב (בלי שמות טבלאות ושדות בקוד, בטיחות SQL), קונבנציות
  והוראות הרצה. הוא עודכן בסוף כל שלב.
- **אימות אחרי כל שלב:** build, הרצת כל הבדיקות ועדכון התיעוד.

**החלטות שקיבלתי במהלך העבודה עם הכלי:** `[להשלמה]`
- `[להשלמה: למשל מבנה הקטלוג שנשלח ל-AI (נתיבי שדות שטוחים), פירוש "משלוח באיחור", החזרת 200 עם isValid=false להצעה לא תקינה]`

## Claude (צ'אט)

**מטרות השימוש:**
- **תכנון ארכיטקטורה:** חלוקה לשכבות (Domain, Application, Infrastructure, Api), שכבת ה-Metadata כמפתח לגנריות, שמירת
  בקרה כ-JSON ולא כ-SQL, והפרדת שירות ה-AI. `[להשלמה]`
- **סקירת תוכניות:** סקירה של התוכניות ש-Claude Code הציע ב-Plan Mode לפני אישורן. `[להשלמה]`
- **הגדרת סביבה:** SQL Server Express, אימות Windows ותעודה self-signed (`-C`, `TrustServerCertificate`), והגדרת npm ו-pip
  מאחורי סינון TLS עם תעודת ה-CA הארגונית. `[להשלמה]`
